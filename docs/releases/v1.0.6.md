# igni app 1.0.6

The desktop app's new look: a Files viewer beside the chat, a sidebar that
says what every chat is doing, and MCPs, Extensions and Plugins as one card
catalogue. It also brings the Local / Cloud switch, updates for Linux and
Windows installs, and the fixes the desktop CI proof found on real Linux,
Windows and macOS machines.

`igni-core` (the backend, the `igni` command, the decisions service) is
released in lockstep with the app: this app installs `igni-core==1.0.6` on
first launch, and the release stops before it builds anything unless PyPI
already serves that version.

## What you get

| | |
|---|---|
| Desktop | `.dmg` (macOS), `.msi` (Windows), `.AppImage` (Linux) — under **Installers** on the release |
| Updater | `latest.json` and each platform's signed payload — `igni_aarch64.app.tar.gz` on macOS, the `.AppImage` on Linux, the `.msi` and the NSIS installer on Windows — for an installed app that updates itself |
| Web UI | inside the desktop app. It is not a separate download, and neither igni-core nor igni server serves it; to use it in a browser, build `clients/web` and host `dist/` yourself |
| Backend | installed on first launch as `igni-core==1.0.6` |

The app starts igni's backend on its own. You do not install Python, `uv` or
`igni-core` yourself — the first launch fetches them.

## What changed

### The sidebar says what every chat is doing

- **Each chat shows its state.** A chat whose run is working shows a small
  turning ring in igni orange. One waiting on your approval keeps its amber
  "waiting" pill, which is now live instead of only as fresh as the last
  session list. One that finished while you were elsewhere gets a blue dot
  and a brighter name until you open it.
- **Read state follows you.** The chat on screen is marked seen while the
  window is visible, once per finished run, so a chat you read in one window
  or on one device is read everywhere.
- **The newest conversation is on top.** Chats are listed by their last
  message. A chat moves to the top the moment a message goes in, in every
  window, before the reply starts. A rename no longer moves a chat.
- **New chat, folders and the account menu moved.** "+ New chat" sits at the
  head of the sidebar, sessions are grouped by folder and each group
  collapses, and the account menu is at the foot of the sidebar, with igni's
  version and the Appearance toggle at its top.

### Files open beside the chat

- **A read-only Files viewer docks to the right of the chat**, opened by the
  folder button in the header, next to the bell. The chat stays live on the
  left. The divider resizes it, its width is remembered on this device, and a
  full-screen toggle hides the chat and the sidebar.
- **Files open as tabs**, and each tab keeps its own scroll position. Open
  tabs survive closing the viewer and are reset only when the project folder
  changes.
- **One search box browses folders and finds files** anywhere in the project.
- **Markdown is rendered**, with its HTML under a sanitizer (`<details>`,
  badges, alignment), code blocks you can copy and collapse, and mermaid
  diagrams. A Source / Preview toggle shows the text, and a link to a file in
  the project opens in the viewer, not in a browser.
- **Images and PDFs are drawn in place.** Other binary files show a card that
  opens them with the system app.
- **A file pill in the chat opens the viewer**, on this computer and in the
  cloud. On the desktop, "Open in editor" is still there.

### Search reaches every chat

- **Chat search has a This chat / All chats scope.** All chats searches every
  conversation in the project, and a result opens the chat it was found in.

### MCPs, Extensions and Plugins read as one catalogue

- **The three pages are one card grid.** Cards are soft and borderless and
  carry an icon (MCP servers had none). The grid flows as masonry: each card
  keeps its own height and the gap between any two cards is the same.
- **One header for all three**: an expanding search, a filter and a sort, as
  quiet icon buttons. The MCPs page's filled "Add server" button is the same
  quiet "+" the Plugins page uses. MCPs filter by connected, disconnected or
  needs approval; Extensions by ready, failed or starting.
- **An MCP server that failed says what to check.** A missing command, an
  address where nothing answers, a timeout or refused credentials read as a
  sentence — for example "Couldn't start “mcp-server-github”: command not
  found. Install it, or fix the command in .mcp.json." The raw error stays in
  the line's tooltip, and an error the app does not recognise is shown as it
  came. The status dot now draws, red for a failure and a quiet ring for a
  server that is only off, and a server's tools are listed without the
  `mcp_<server>_` prefix.
- **The MCPs page reloads `.mcp.json`.** A refresh button in its header picks
  up a server you added, edited or removed, without restarting the app.
- **An extension opens onto its own page**, the way a plugin does: settings,
  the pages and commands it adds, its tools and its notices. The card itself
  is a compact summary — icon, name, version, state and a one-line reason.
  The settings form uses the design system's fields, selects and switches,
  and "Open on the web" lives on that page.
- **Plugins show their category.** Each category has an icon, used as the
  card's avatar and beside each option of the category filter, and the
  marketplace sorts and filters by it. The Installed tab uses the same card
  grid as the Marketplace tab, and the install field looks like the chat's
  composer.
- **Extension cards are readable in dark mode.** Their id and version were
  drawn black on the dark card.

### The chat uses the whole window

- **Messages fade out under a blurred top edge** instead of being cut at the
  header's solid band, and the conversation uses the window's full height.
  The sidebar's session list fades the same way under "+ New chat".

### Approvals and Stop

- **Stop shows while an approval waits.** It takes Send's place, and it does
  what Escape does: rejects the waiting approvals and stops the run. The
  indicator says "Waiting for your approval" instead of "Finalizing…", the
  approval dialog shows "Esc rejects all and stops", and a message typed then
  starts a new run instead of queueing behind the paused one.
- **An approval the backend dropped leaves the screen.** Sending a new
  message instead of answering used to leave the old card up, and its
  buttons failed with "Unknown requirement".

### This computer or the cloud

- **The desktop can run igni on this computer or in your cloud igni**, as
  your group's mode allows. A group in `local` mode sees nothing new and the
  app never dials the cloud. In `local_and_cloud` mode, *This computer ·
  Cloud* sits in the account menu. In `cloud` mode the app runs only a small
  backend for sign-in and the group's policy, and the status line's chip
  shows Cloud with no switch. A mode change applies while the app runs.
- **The status line says how the cloud is doing**: `Cloud`, `waking…`,
  `sign in` or `offline`. Banners cover signing in, an unreachable cloud
  (with **Use this computer** when that is allowed), a refusal and a busy
  cloud, and a badge counts runs and approvals still waiting on this
  computer.
- **Extensions work in the cloud.** Their pages are served through the
  shell, which proxies the gateway's page route.
- **Your session token never enters the window.** The shell relays the
  connection over loopback with a per-launch token and dials the gateway
  over verified TLS, honouring `HTTPS_PROXY` and `NO_PROXY`. The window's
  content security policy still names nothing off this machine.
- What needs a path on your computer — opening or revealing a file, the
  folder picker, the hooks panel's file links — is hidden in the cloud, and
  *Restart* and *Reinstall* say "(this computer)".

Until a server offers a cloud igni, the app finds none and behaves as it did
before.

### Updates, certificates and the installs

- **Linux and Windows installs are offered updates**, not only macOS ones.
  `latest.json` now carries the AppImage, the `.msi` and the NSIS installer,
  each with its own signature, and each install fetches only its own. A
  `.deb` or `.rpm` install is not offered the AppImage.
- **A certificate problem says so.** The updater's error used to be "error
  sending request"; it now names the cause, and for an unknown issuer it
  says to add your organisation's CA to the system's trust store.
- **The first-launch `uv` download trusts the system's certificates and
  your proxy.** It used a built-in root list and ignored `HTTPS_PROXY`, so a
  first launch behind a company's TLS-inspecting proxy failed even with the
  company's CA installed.
- **A backend that crashes is started again**, and every window follows it.
  The app gives up after three crashes in five minutes.
- **The Linux menu works.** Close, Minimize and Maximize were greyed out;
  they are the app's own items now, and Undo and Redo, which the window
  handles itself, are gone from the menu.
- **Windows gets the native bridges, the menu and `igni://` links.** The
  window's start-up script stopped at its first line on Windows, so external
  links, menu events and `igni://` links never reached the page.
  Ctrl+N, Ctrl+Shift+N, Ctrl+Q and F11 work while the page has focus, a
  menu action goes to the window you used it in, and a restart no longer
  attaches to the backend that is shutting down.
- **The Windows build compiles again.** `zip` 9 changed how a zip entry's
  name is read, which broke the Windows leg of the 1.0.5 release build. A CI
  job now compiles and tests the Windows-only code on every push.

### The chat in a browser

- **Two tabs of one browser follow the same chat, and both work.** The
  older tab used to drop every event of the new chat. A scroll in one tab no
  longer moves the other.

### The visualizer's card

- **A chart drawn from a model's slightly different data is drawn.** A list
  wrapped in an object under a single `item` key is read as the list, and a
  number written as text is read as the number. Text that is not a number is
  not guessed at: the card says the values are not numbers.
- **A card that could not draw everything says what it left out**, live and
  when the chat is opened again, and a component type the catalogue does not
  know counts as a failure.
- **The card tells the backend what it drew**, so the agent's recap says
  what the card actually shows instead of "Rendered" over an empty card.

The test plan is in the same release. `docs/ENTERPRISE_TEST_PLAN.md` lists
248 scenarios with stable ids, and the suite that runs them adds scenario
specs against a real backend and a deterministic scripted model, so the
specs that need a model run in CI with no API key. New desktop jobs install
and drive the app on Linux, Windows and macOS. The Local / Cloud switch's CI
runs a full chat turn through the shell's relay, and each switch screen has
its own visual baseline.

The backend that comes with it (`igni-core==1.0.6`) carries the other half
of several of these:

- **The chat states**: every window is told which chats are running, waiting
  or unread, read state is kept across windows and devices, and chats are
  listed newest first by their last message.
- **The MCP reload re-reads `.mcp.json` on every call**, including the first
  connect.
- **Image and PDF previews and the all-chats search** (`read_file_bytes`,
  `search_all_chats`), and the plugin category the marketplace filters by.
- **Cancelling a run that waits on an approval ends it**, and a new message
  drops the approvals of a paused run.
- **The cloud switch's backend**: the group's `mode`, `--account-only`, and
  extension pages through the gateway.

## What is still open

- **A message a `UserPromptSubmit` hook blocks leaves an old approval card
  up.** No run starts, and nothing on the wire says the approvals were
  dropped.
- **The cloud switch needs a server that offers a cloud igni.** The CI step
  that drives an extension page, the host model and its service token
  through a real cloud waits on igni-core's cloud page files; until then the
  shell is tested against a stand-in gateway.
- **Initials in a monogram avatar can be hard to read.** igni-sdk's Monogram
  draws white initials on a colour that falls below WCAG AA for 165 of the
  360 hues. The fix belongs in igni-sdk.

## Upgrading

An app installed from an earlier release updates itself: the updater reads
`latest.json` and the installed app checks the payload's minisign signature
against the public key it ships with. From this release that includes
Windows and the Linux AppImage. A `.deb` or `.rpm` install is upgraded by
installing the new package over the old.

Nothing about your settings, sessions or connections moves. They live in the
backend, and the backend is upgraded to `igni-core==1.0.6` with the app.
Its first start adds one table to the global database, for the chats'
read state.

## Verify

`SHA256SUMS` lists every file on the release, and each one carries a build
provenance attestation and, for the desktop app, a CycloneDX SBOM
(`igni-desktop-1.0.6.cdx.json`). The full procedure — checksums, provenance
online and on an air-gapped machine, and the cosign signature once the key
ceremony has happened — is in [VERIFYING_RELEASES.md](../VERIFYING_RELEASES.md).

```bash
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify igni-desktop-installer.dmg \
  --repo ignite-ember/igni-app \
  --signer-workflow ignite-ember/igni-app/.github/workflows/release.yml \
  --source-ref refs/tags/v1.0.6
```
